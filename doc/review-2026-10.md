## 1. Soundness

Each claim was re-derived by an independent second review pass against the code and the SDK
headers; one claim was refuted (M2) and is kept for the record. A third pass (Codex, 2026-10-21)
added H11 to H13 and M9 to M11 and corrected two statements, marked "corrected" below.

Severity: **H** = UB reachable from safe code or a memory-safety bug; **M** = UB by the rules but
unlikely to miscompile today, or a correctness bug that is memory-safe; **L** = hygiene.

### H1. `&mut Wrapper` on the audio thread aliases `&Wrapper` on other threads
`median/src/wrapper.rs:398` `MSPWrapperInternal::perform64(&mut self, ..)`, `:799` `perform64(&mut self)`,
`:824` `dsp64(&mut self)`. Message trampolines take `&self` and run on main/scheduler threads
concurrently with perform. Holding `&mut T` and `&T` to the same object at the same time is UB
regardless of which fields are touched. `Wrapper::wrapped_mut` (`:524`) is also a safe pub fn.
Fix: `perform64(&self)`; keep the slice scratch (`ins`/`outs`) in an `UnsafeCell` with the documented
invariant that Max never re-enters perform for one object, or build the `&[&[f64]]` views on the
stack each call (numins/numouts are small).

### H2. `dsp_in_place() -> bool` lets a safe trait method request aliasing slices
`wrapper.rs:149`. Returning `true` clears `Z_NO_INPLACE`, so Max may hand the same buffer as an
input and an output; `perform(&self, ins: &[&[f64]], outs: &mut [&mut [f64]])` then holds a shared
and a mutable slice over the same memory. Fix: drop the option, or make it `unsafe fn` and change
the perform signature for in-place objects to `&mut [&mut [f64]]` only.

### H3. Blanket `unsafe impl MaxObj for T` on any `T: MaxObjWrapped<T>`
`wrapper.rs:895-927`, `object.rs:85-105`. `max_obj()` subtracts two field offsets from `self`. It is
only valid when `self` lives inside a `Wrapper`. Any `T` constructed elsewhere (tests, a helper that
builds a `T` and calls `t.post(..)`) gives Max a wild pointer from safe code via `impl_obj_methods!`.
This is also why the design needs `field-offset`. Fix: do not implement `MaxObj` for `T`; give the
user an explicit `ObjRef` handle from the builder (Max allocates the object before `T::new`, so the
pointer is known), store it in `T`, and derive `post`/`attr_touch`/`notify` from the handle.

### H4. `num::Float64` / `Int64` are non-atomic `UnsafeCell`s declared `Sync`
`num.rs:10-59`. `set` on the scheduler thread racing `get` on the audio thread is a data race (UB in
Rust's model; hardware atomicity is irrelevant). Fix: `AtomicU64` with `f64::to_bits`/`from_bits`,
`AtomicI64`; drop the `target_arch` gate.

### H5. `SymbolRef` has interior mutability without synchronisation and a safe raw constructor
`symbol.rs:12-34`. `assign(&self)` through `UnsafeCell<*mut t_symbol>` on a `Sync` type is the same
race class as H4; `SymbolRef::new(ptr)` is safe and `to_cstring()` dereferences
(`SymbolRef::new(null_mut()).to_cstring()` is a null deref from safe code). `inner_ref` (`:36`)
also manufactures `&mut t_symbol` from `&self` to a process-global symbol that Max mutates
(`s_thing`) and that two threads can `Display` at once. Symbols are interned
and never freed, so the right shape is a `Copy` newtype over `NonNull<t_symbol>` with an `unsafe
fn from_raw`; put the mutability in the owner (`AtomicPtr`, or the mutex `BufferRef` already has).

### H6. Buffer notification writes through a pointer derived from `&name` on an immutable local
`buffer.rs:124-132`. `let name = null_mut(); object_method(data, GET_NAME, transmute(&name)); if
!name.is_null() ..`. Max writes through a pointer derived from a shared reference to a local with no
interior mutability; the compiler may assume `name` is still null and remove the branch. Works today
because the pointer escapes into an opaque call, but it is UB and Miri rejects it. Fix: `let mut
name` and `&raw mut name as *mut c_void` (or `&mut name as *mut _`).

### H7. buffer~ lock hands out `&mut [f32]` over a shared claim
`buffer.rs:201-219, 265-342`. `buffer_locksamples` is a shared claim ("so that other objects may
read/write", `ext_buffer.h`). Two `try_lock()` calls on the same `BufferRef` from safe code each
yield `channel_slice_mut`, so two `&mut [f32]` alias the same samples; and any `&[f32]` held while
`record~` writes on the audio thread breaks the shared-reference immutability guarantee. Sample
access through this lock has to be raw-pointer, `Cell<f32>`, or atomic views; `&mut` is only
honest under `buffer_edit_begin/end`, which median does not wrap.

### H8. Inlet callbacks and clock closures have no `Send + Sync` bound
`inlet.rs:5-7` `FloatCB<T> = Box<dyn Fn(&T, f64)>`, `builder.rs:47` `with_clock(Box<dyn Fn(&T)>)`.
They are stored in the shared wrapper and invoked from main and scheduler threads. A closure that
moves a `Cell` in and bumps it races from safe code; `T: Sync` does not cover captures. Add
`+ Send + Sync`.

### H9. Safe public functions that dereference caller-supplied raw pointers
This is what clippy's 19 `not_unsafe_ptr_arg_deref` errors are. `attr::get`/`set` (`attr.rs:419,
440`), `method::sel_list` (`method.rs:24`), `Proxy::new` (`inlet.rs:30`), `Outlet::append_*`
(`outlet.rs:44-80`), `thread::defer`/`defer_low`, `object::post`/`error` (`object.rs:111,122`),
`Slice::from_raw_parts_mut`, `SymbolRef::new`. `attr::set(1, 0x10 as _, |_: f64| {})` is UB from
safe code. Mark them `unsafe fn` with a `# Safety` section; the wrapper's generated trampolines are
the only legitimate callers.

### H11. Console output passes user text as a printf format string
`max.rs:17,28`, `object.rs:114,125`. `post`, `error`, `object_post`, `object_error` are variadic
printf-style (`ext_post.h:43,84,200`). median passes the formatted message as the *format*
argument, so `post!("{}", "100%s")` makes Max read nonexistent varargs. Fix: `post(c"%s".as_ptr(),
msg.as_ptr())`, same for the object variants, or use `poststring`/`post_sym` where available.

### H12. Attribute accessor trampolines have the wrong C signature
`attr.rs:13-16`, `tramp.rs:167,200`. The SDK accessors are
`t_max_err get(t_object *x, void *attr, long *ac, t_atom **av)` and
`t_max_err set(t_object *x, void *attr, long ac, t_atom *av)` (`ext_obex.h:1554`). median declares
`attr: c_void` by value and returns `()`; the generated trampolines compute a `t_max_err` from
`attr::get`/`set` and then discard it, so Max reads a garbage return register. Fix the type
aliases (`*mut c_void`, `-> t_max_err`), `get_nop`/`set_nop`, and the generated functions.

### H13. `dsp64` trampoline uses `i64` where the SDK uses C `long`
`wrapper.rs:740-741, 829-830`. `maxvectorsize` and `flags` are `long` in the SDK
(`simplemsp~.c:25`), which is 32-bit on Windows. Use `c_long`. (Found while re-checking H1; the
`&mut Self` to `&Self` change alone does not fix it.)

### M1. buffer~ channel access assumes planar data; Max buffers are interleaved
`buffer.rs:247-278`, `344-412`. `channel_slice(ch)` returns `samples[ch*frames .. +frames]`. The SDK
(`ext_buffer.h:35`) says samples are "stored with interleaved channels if multi-channel". In bounds,
so memory safe, but wrong for every multichannel buffer. A channel cannot be a plain `&[f32]`;
expose frame slices (`frame(i) -> &[f32]` is contiguous), a strided channel iterator, and
`sample(frame, ch)`.

### M2. (withdrawn) Assist copy length
I suspected `ASSIST_MAX = 512` overruns Max's buffer because `ext_assist.h` says
`ASSIST_MAX_STRING_LEN = 500`. The SDK docs (`doxygen/content/api_14_enhancements.h:42`) say 512 is
the buffer size and 500 is a recommended content limit, and the SDK's own example copies 512.
Not a bug.

### M3. `attr::set` leaks an unbounded lifetime
`attr.rs:440-453`: `T: From<&'a Atom>` with `'a` chosen by the caller and the reference produced by
transmute, so a setter can retain `&'static Atom` to Max-owned memory. Fix with an HRTB.

### M4. `Slice<T>` assigns into uninitialised memory, trusts `len()`, and can double free
`slice.rs:14-28, 83-102`: `*v = Default::default()` on fresh `sysmem_newptr` memory runs the drop glue
of garbage for any `T: Drop` (`Slice::<String>::new_with_length(1)` frees a wild pointer); use
`ptr::write`. `size_of::<T>() * len` is unchecked (`:17, :91`), so a huge `len` wraps in release,
allocates a small block and then writes `len` elements. `From<U: ExactSizeIterator>` trusts
`len()`, which is a safe trait to implement wrongly, leaving uninitialised `T` reachable via
`as_ref()`. `Drop` (`:72`) frees the storage without dropping any element, so every `Slice<T: Drop>`
leaks its contents. `from_raw_parts_mut` (`:40`) is safe and `Drop` frees, so calling it twice on one
pointer is a safe double free (the module's own test is one line away from it). `sysmem_newptr`
only guarantees malloc alignment, so `T` with `align > 16` is UB here and in `alloc.rs`
`MaxAllocator::alloc`, which ignores `layout.align()`; std's `mpsc` channel uses `align(128)`
padding, so a `MaxAllocator` user who creates a channel gets a misaligned `Box`.

### H10. `ObjBox::value` is `pub`, which makes `Wrapper::drop` reachable: double free from safe code
`object.rs:137` `pub value: Option<Box<T>>`, `wrapper.rs:883-893`. `let mut o =
MaxObjWrapper::<T>::new_noargs(); drop(o.value.take());` runs `Wrapper::drop`, which calls
`object_free` (Max runs `free_wrapped` and frees the memory), then `Box` frees the same pointer
through the Rust global allocator. `ObjBox: DerefMut` also lets safe code `mem::swap` two live
`t_object` headers whose inlets point back at their owners, and hands out `&mut Wrapper` to an
object Max can call into concurrently (see H1). Fix: private `NonNull<T>` field, no `DerefMut`,
remove `impl Drop for Wrapper` (the Box-around-foreign-memory invariant violation is real but
has no practical effect once the field is private).

### M6. Clock callback trusts that the owning object outlives the `ClockHandle`; clocks leak
`clock.rs:109-162`, `builder.rs:290-313`. The callback transmutes the stored owner pointer to `&W`.
`ClockHandle` is `Send + Sync + 'static` and movable; a `T` holding it in `Mutex<Option<_>>` can
`take()` it with `&self` and park it in a `static`; after the Max object is freed, `delay()` fires
into a dangling pointer. `Drop` only calls `clock_unset`; the SDK says clocks are released with
`freeobject()` (`ext_proto.h:664`), so every clock leaks. `clock_unset` does not wait for an
in-flight callback, so dropping the handle off the scheduler thread can free `_target` under a
running callback. Note `clock_new_withscheduler` exists and would replace the `#S` obex hack.

### M9. Offset attributes are dead: no-op accessors override the SDK defaults
`attr.rs:229-246`. `AttrBuilder::build` substitutes `get_nop`/`set_nop` whenever a getter or setter
is absent, including for `attr_offset_new`. The SDK installs its default offset accessors only
when the method pointers are NULL (`ext_obex.h:1626` passes `(method)0L`). So every
`new_offset*` attribute without both accessors neither reads nor writes the field. Pass `None`
through; use no-ops only when an operation is deliberately disabled.

### M10. Outlet handles can outlive their object
`builder.rs:321-373`, `outlet.rs:13-14,36-42`. `OutList` and friends are `Box<dyn .. + Send + Sync>`
with no tie to the owner. Moved out of the object (into a `static`, another object) they call
`outlet_list` on a pointer Max freed with the owner. Same class as M6; the redesign's outlet
descriptor must be non-`Clone` and only borrowable from `&self`.

### M11. The test stubs' allocator is itself UB
`median/src/test/sysmem.rs:6-16`. `sysmem_newptr` leaks a `Box<[i8]>`, `sysmem_freeptr` rebuilds a
`Box<c_void>` from the pointer, so the deallocation layout is wrong, and byte allocations give no
alignment for the tested `T`. Any future mock must record the layout (or call `libc::malloc`/`free`).
*Fixed:* the stubs are gone; median's tests link `median-mock`, whose `sysmem_*` keep the size.

### M7. Panics abort Max; registration failure exits Max
Since Rust 1.81 a panic escaping an `extern "C"` fn aborts the process. Every trampoline, `new_tramp`,
`perform64` and the many `assert!`/`expect` calls in the construction path (`builder.rs:237,241`,
`wrapper.rs:457,590`) therefore take Max down. Before the abort, a panic in `T::new` unwinds through
`new_tramp` and drops the `ObjBox` (`wrapper.rs:671`), which runs `free_wrapped` and
`assume_init()`-drops the never-written internals (`:533`). `median_macros/src/external.rs:45-75` catches the
registration panic and calls `std::process::exit(1)`, which also kills Max. The template's release
profile sets `panic = "abort"`, which makes `catch_unwind` a no-op anyway. Fix: `panic = "unwind"` for
the cdylib, `catch_unwind(AssertUnwindSafe(..))` in every generated trampoline, report via
`object_error`, return a sane default (null from `new_tramp`, which Max treats as creation failure).

### M8. `T::new` cannot fail
`MaxObjWrapped::new(builder) -> Self`. In the C SDK and in min (which throws), a constructor can
refuse bad arguments and Max prints an error and leaves an empty box. Here the only option is a
panic (see M7). Make it `-> Result<Self, impl Display>` or `Option<Self>`.

### L. Hygiene
- `file.rs:101-106` copies the name with `zip` into `[c_char; 2048]`, silently truncating; a name of
  2048+ bytes has no NUL and `locatefile_extended` over-reads the stack from safe `FilePath::locate`.
  `n as i8` only matters if Linux aarch64 ever becomes a target. `:186-195` ignores
  `sysfile_readtextfile`'s return and dereferences a possibly-null 0-byte handle.
- A `T` implementing both `MaxObjWrapped` and `MSPObjWrapped` gets both blanket `MaxObj`/`MSPObj`
  impls and `max_obj()` then uses the wrong layout's offsets.
- `H3` note: `MaxWrapperInternal` not being `#[repr(C)]` is fine; `field-offset` measures the real
  monomorphised layout with `addr_of`.
- `error.rs:22` and the dict branch use `println!` for unknown codes; use `max_sys::error`.
- `SymbolRef::fmt` panics on non-UTF-8 symbols; use `to_string_lossy`.
- `register_common` holds the `CLASSES` mutex across `class_setup`, with a documented deadlock.
- Error enums (`SendError`, `MaxError`, `LocateError`, ...) have no `Display`/`Error` impls.
- `Class::add_sel_method` has an `unimplemented!()` arm for >7 args. (Corrected: `build.rs`
  generates permutations up to length 7, so it is unreachable today; it becomes reachable if
  the generator is extended.)

## 2. Ergonomics of the current API

- `impl MaxObjWrapped<Simp> for Simp` repeats the type; the `T` parameter on `ObjWrapped<T>`,
  `MaxObjWrapped<T>`, `MSPObjWrapped<T>` is always `Self`.
- One attribute takes four edits: a getter fn with `#[attr_get_tramp]`, a setter fn with
  `#[attr_set_tramp]`, an `AttrBuilder::new_accessors(..).build().unwrap()` in `class_setup`, and
  the field. min: one line. The builder only knows `clip` and visibility; no label, style, category,
  order, default, enum, readonly, save.
- A custom selector takes two edits (`#[tramp]` plus `c.add_method(Method::SelS("set", Self::set_tramp, 0))`).
- Outlets are `Box<dyn SendValue<T> + Sync>` trait objects. A concrete `Outlet<Int>` type is simpler,
  faster and `Copy`-able.
- The builder's every `add_*` has a `_with_assist` twin (10 methods for 5 outlet kinds) and the
  default inlet's assist is a separate call. Assist and inlet kind should be one descriptor.
- `builder.creation_args()` includes the `@attr` tail; there is no `attr_args_offset` helper and no
  typed argument declaration (min: `argument<>`).
- `SymbolRef::try_from("blah").unwrap()` at every call site. `c"blah"` literals already work via
  `From<&CStr>`; document that, or add a `sym!()` macro that validates at compile time.
- All state must be interior-mutable but the crate only ships the (unsound) `Float64`/`Int64`; no
  guidance for `Mutex`/atomics, no "main-thread-only" state container.
- `external! { .. }` wraps the struct and every impl. rustfmt will not format inside a function-like
  macro with braces, and rust-analyzer resolves everything through the expansion (see §5).
- Generated `Method::SelIS..` permutations (median/build.rs) give typed selector methods that min
  does not have. Good idea; keep it, but the `build.rs` with syn/quote could be a `macro_rules!`.

## 3. What min has that median does not

Read from min-api headers. Items marked (*) are places median's design can do better than min.

Object model
- Fallible construction (`error()` throws; Max shows an error and an empty box). Median cannot fail (M8).
- UI objects (`ui_operator`, `jbox_new`, paint/mouse/focus/key events, color attributes tied to Max
  styles). Median: none.
- MC objects (`mc_operator`, minimal in min). Median: none.
- Jitter `matrix_operator` with per-cell `calc_cell` templates. Median: `feature/jitter` branch only,
  but that branch also has MOP parallel calc and the start of ob3d, which min does not have (*).
- Per-sample DSP (`sample_operator<IN,OUT>` with compile-time I/O counts). Median only has the
  vector form; a `SampleOp` adapter over `perform` is cheap to add.
- Class flags: `nobox` (median has), `no_live`, `do_not_generate` docs.
- Special messages handled by the wrapper: `dblclick`, `loadbang`, `savestate`/`appendtodictionary`,
  `patchlineupdate`, `fileusage`, `edclose`/`okclose`, `dspstate`, `oksize`, `getplaystate`, mouse and
  focus events. Median: `notify`, `assist`, `dsp64` only.
- `dictionary` message with retained dict atom; `#D` state dict for `savestate`.

Attributes and arguments
- One-line attribute declaration with `title`, `description`, `range`, `limit::{clamp,wrap,fold}`,
  `style`, `category`, `order`, `readonly`, `visibility`, `enum_map`, `live_color`, default,
  `allow_repetitions`, custom setter/getter, thread policy, `time_value` (ITM) attributes, vector
  attributes (`numbers`, `ints`), `ui::color`. A `value` attribute auto-wires pattr/preset.
- `argument<T>` declarations processed in order before `@attr` args.

Threading
- `outlet<thread_check, thread_action>` with `assert | fifo | first | last` delivery via qelem/clock.
- `message<threadsafe::no>` and attribute setters auto-defer to main (lossy: fifo depth 2).
- `queue<>` (qelem), `timer<>` (clock, optional defer delivery), `fifo<T>` (SPSC lock-free).
  Median has `ClockHandle` and raw `defer`/`defer_low`; no qelem, fifo, or policy types.

Support types
- `dict` (median: branch), `path` (system folders, enumerate, copy; median: locate + dialog + read
  text), `patcher`/`box`/`instance` access via `#P`/`#B` with `object_method_typed` dispatch,
  `texteditor`, `time_value` and dataspace conversions, `logger` with `cwarn` (median lacks
  `object_warn`), string helpers, `limit`/`wrap`/`fold`/`scale`.
- `buffer_lock<audio_thread_access=false>` using `buffer_edit_begin/end`, `resize`, `length_in_seconds`,
  `lookup(frame, channel)` with clamping, auto `set`/`dblclick`/`notify` messages. Median: lock only,
  planar bug (M1), no edit lock, no resize.

Docs, tests, build
- `.maxref.xml` generated at runtime from declarations (digest/description/author/tags, args,
  messages, attributes, seealso; no inlet/outlet docs). (*) Rust can generate this at build time
  from derive metadata, with inlet/outlet assist included, and no runtime file writes.
- Catch-based unit tests against a mock Max kernel (`Cycling74/mock`), `test_wrapper<T>`,
  `object_getoutput` to observe outlet traffic, CI on mac (fat) and Windows. Median: 3 unit tests
  and hand-written `#[no_mangle]` stubs for 3 SDK functions; `feature/maxcore-test` links a private
  MaxCore build. A `median-mock` crate (Rust re-implementation of the subset, or linking
  `Cycling74/mock`) is the single biggest testing gap.
- CMake package layout, `package-info.json.in`, fat binaries by default, `create_package.rb`.
  Median: cargo-make with the template downloading `Makefile.toml` from `develop` at build time
  (unpinned), ad-hoc codesign, no `Info.plist`, Max 8 install path on develop.

Where median is already ahead or can be
- Typed selector methods (`Method::SelIS(..)` with defaults) vs min's all-`A_GIMME` dispatch by
  string lookup per call.
- Hot/cold inlets: min has no `inletinfo` support at all; the `xnor/inletinfo` idea is a real
  differentiator.
- Compile-time reflection via derive instead of min's dummy-instance construction at `ext_main`.

### 4a. Details
xnor/linux
- Switches the submodule from `max-sdk` (Max 8 SDK, pinned June 2021) to `max-sdk-base`; adds
  `ffi-linux-x86_64.rs` (bindgen 0.55.1, jitter excluded via `#ifndef LINUX_VERSION`); Makefile gets
  `MAX_VERSION = "Max 9"` (overridable) and Linux `env/build/package/install` tasks.
- Fix before merge: root README link points to `max-sys-base/README.md` (wrong path); `rustfmt.toml`
  `merge_imports = true` is an unstable, removed option; the generic `build` task still only
  dispatches on mac/windows flags so `cargo make build` on Linux does nothing; mac and windows

  aarch64 Linux (`c_char = u8`). Because the template downloads develop's Makefile at build time,
  the Max 8 to Max 9 install path change hits every template user immediately on merge.
- Open question: Max has no public Linux runtime. If the target is an internal Linux Max or RNBO,
  say so in the README; otherwise the Linux bindings are dead weight for external users.

feature/dict (assessment as of the review; the decision afterwards was to redesign rather than
fix, see [plan-containers.md](plan-containers.md))
- Must fix: `dict.rs:299` `from_raw_parts_mut(null, len)` for empty dicts (same class develop just

feature/jitter

  does not build on aarch64 or Windows. `parallel.rs:134` `let m1i = m0.info()` should be `m1.info()`.

  Jitter long matrices are 32-bit (`t_int32`), so iteration overruns rows. `iter.rs:211`
  `entry_iter(&self)` yields `&mut [T]`, so two calls alias. ob3d is WIP (`GLGeometry`/`GLDataBuffer`
  have no constructors).
  Adds required methods to `MaxObj`/`MSPObj` (breaking); the gl example registers `assist` by hand
  and will collide with develop's built-in assist. Also carries its own submodule rename.
- It is the most valuable branch (min has no gl at all), so worth the rework: fix the above, gate
  `jit` behind a cargo feature until all bindings are regenerated, land after the dict work.

### 4b. Assist and inletinfo
What is wrong today
- Index bug on every MSP object that mixes signal and non-signal inlets (traced by hand against the
  SDK docs, not run): signal inlets are pushed into `inlets` and every entry gets `index + 1`, but
  the first signal inlet *is* the default inlet. With one signal inlet and one int inlet (the
  `index~` shape) the int sits at position 1 but its assist key is 2. The `index < 10` assert also
  counts signal inlets, so 9 signals plus one float panics.
- Creation order is backwards: `finalize_inlets` reverses the list, so `floatin`/`intin`/`proxy_new`
  run *before* `z_dsp_setup`. `z_dsp.h:298` says to call `dsp_setup()` first and create non-signal
  inlets after it. Whether the reversed order is merely fragile or actually misplaces inlets needs a
  run in Max.
- The `_with_assist` doubling and the `with_default_inlet_assist` special case.
- Dynamic assist (`ObjWrapped::assist`) hands the user a `FnOnce(&CStr)` renderer; the user has to
  build a `CString` and `unwrap`.
- `xnor/inletinfo` adds `inlet_cold(index)` and the trampoline, but never registers `"inletinfo"`
  with `class_addmethod`, so the trampoline is dead code. The default ("all but 0 cold") is what
  `stdinletinfo` already does, so the branch only matters when a user overrides it.

Suggested shape
- One descriptor per iolet: `Inlet::proxy().assist("...").hot()`, `Inlet::float(cb)`, `Inlet::signal()`,
  `Outlet::list().assist("...")`. The builder records kind, assist, hot/cold, and the final position.
  `assist`, `inletinfo` and (later) maxref generation all read the same table.
- Builder computes positions in `finalize`: for MSP, `n` signal inlets occupy 0..n and are forced to
  be leftmost; everything else follows in declaration order; `in<N>`/`ft<N>` ids are allocated
  independently of position.
- Dynamic override stays on the trait but returns `Option<Cow<'_, str>>`; the wrapper converts to C
  and copies with `ASSIST_MAX_STRING_LEN`, falling back to the table, then to "inlet N".
- Register `inletinfo` only when any inlet is declared hot (otherwise `stdinletinfo` is correct).

## 5. Rust features worth adopting (verified against stable 1.94; current stable is 1.99)

Direct replacements
- `core::mem::offset_of!` (1.77; nested fields 1.82) replaces `field-offset`. Better: remove the
  offset arithmetic entirely (H3).
- `std::sync::LazyLock` (1.80) replaces `lazy_static`.
- `c"..."` literals (1.77) replace `CString::new("x").unwrap()` at every registration site.
- `AtomicU64::from_bits`-style wrappers replace `Float64`/`Int64` (H4).
- `&raw mut` (1.82) for pointers into Max-owned memory (H6).
- `bindgen` 0.73 (0.55 is from 2020): `--generate-cstr`, `--wrap-unsafe-ops`, `unsafe extern`
  output, `--rust-target`. `syn` 3 is current; `paste` is unmaintained (`pastey` is the fork).

Edition 2024 (1.85)
- `unsafe extern` blocks, `#[unsafe(no_mangle)]`, `unsafe_op_in_unsafe_fn` warn-by-default, `if let`
  chains (1.88, 2024 only). The crate is still on 2018; `cargo fix --edition` twice is cheap.
- Since 1.81 a panic across `extern "C"` aborts (M7). Do not use `"C-unwind"`; catch at the boundary.

Diagnostics
- `#[diagnostic::on_unimplemented]` (1.78) on `MaxObjWrapped`/`MSPObjWrapped` to say "wrap the type
  with the derive" when a user forgets.

Macro and LSP strategy
- rust-analyzer handles `#[derive]` on a struct best (the item stays in source), then attribute
  macros that re-emit their input unchanged with original spans, and is weakest on function-like
  macros that swallow whole items. rustfmt also skips the body of `external! { .. }`.
- Proposed split: `#[derive(MaxObject)] #[max(name = "simp", kind = msp)] struct Simp { #[attr(..)] gain: AtomicF64, .. }`
  generates the wrapper type, registration, offset-based or generated attribute accessors from
  field annotations; a thin `#[median::methods] impl Simp { #[bang] fn bang(&self) .. }` re-emits the
  impl verbatim and adds sibling trampolines plus a `fn __register_methods(c: &mut Class)`.
- Alternative that needs no proc macro for methods at all: a generic trampoline over a ZST closure
  type. `fn bang<T, F: Fn(&T)>(_: F) -> extern "C" fn(&Wrapper<T>)` returns `tramp::<T, F>` where
  `tramp` materialises the closure with `MaybeUninit::zeroed().assume_init()` guarded by a
  `const { assert!(size_of::<F>() == 0) }`. Then `c.add(Method::bang(|s: &Simp| s.bang()))` is plain
  Rust with full IDE support. (Stable; the "ZST closure as function" trick is used by several C
  callback crates.) String const generics (`const NAME: &str`) are still unstable, so selector
  names stay runtime values.
- Still unstable, do not wait for them: `macro_rules!` attributes (RFC 3697), `macro_metavar_expr`,
  `adt_const_params`, `generic_const_exprs`, `Allocator`, `negative_impls`.

Cargo
- `[lints]` table (1.74) to turn `unsafe_op_in_unsafe_fn` and `clippy::not_unsafe_ptr_arg_deref` into
  errors; `[workspace]` at the repo root (there is none, so `cargo test` must be run per crate).
- `panic = "unwind"` in the template's release profile (M7).
